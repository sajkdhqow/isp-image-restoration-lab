# ML 化 ISP 笔记 —— 端到端低照度成像(SID 风格)

记录把传统 ISP 流程改造成机器学习方法的完整过程: 动机、方案选型、
实现、踩坑、最终结果与诚实的结论。对应代码在 `ml/` 目录。

## 1. 动机: 传统 ISP 的结构性局限

传统 ISP 是一条人工设计的模块链(DPC→BLC→BNR→LSC→AWB→Demosaic→
CCM→Gamma→...), 每个模块在自己的目标上局部最优。三个结构性问题:

1. **误差级联**: 上游模块的假设错了(AWB 在单色场景翻车), 下游
   无从纠正;
2. **模块间目标不一致**: BNR 追求去噪, EE 追求锐化, 两者在边缘上
   拉锯, 参数靠人肉平衡;
3. **极端场景失效**: 低照度下信号接近噪声底, "先去噪再拉伸"的
   分模块思路信息损失不可逆 —— 而这正是手机夜景最需要的场景。

端到端方案(Learning to See in the Dark, CVPR 2018)的思路: 用一个
网络直接学 RAW→sRGB 的映射, 让"去噪/去马赛克/白平衡/色调映射"
在同一个目标下联合优化。参考实现: cydonia999/Learning_to_See_in_
the_Dark_PyTorch(端到端 U-Net), SpunkySam-cyber/Low-light-image-
enhancement-using-Unet-architecture(sRGB 域增强变体)。

## 2. 方案选型

| 方案 | 说明 | 取舍 |
|------|------|------|
| 端到端 U-Net(本仓库采用) | 低照度 Bayer RAW 直接输出 sRGB | 展示冲击力强, 面试故事完整; 训练数据决定上限 |
| 模块级替换 | ML 只替换单模块(如 NR) | 训练快, 风险低, 但展示效果弱 |
| 混合方案(工业界主流) | 传统 pipeline 主体 + ML 降噪/插值 | 产品化路径, 手机 ISP 的真实形态 |

本仓库选端到端以对齐参考项目; 面试时要能讲清"产品落地一般是混合
方案, 端到端是研究边界"。

## 3. 实现 (ml/ 目录)

### 3.1 数据: 在线合成配对数据 (data.py)

SID 用真机短曝-长曝图像对(18GB); 本仓库用 `tools.simulate_raw`
合成等效数据:

- 输入: 场景 x 随机低曝光(0.0075~0.08, 即 1/13~1/133 正常照度)
  x 极端噪声(sigma_read=3DN + 强散粒) -> BLC -> packed Bayer
- GT: 场景 sRGB 真值(合成数据的红利: 真实拍摄拿不到逐像素真值)
- **在线随机场景生成**: 每个样本随机生成布局/配色/渐变/条纹都不同
  的场景, 等效无限训练集

### 3.2 模型: LightUNet (model.py)

- 输入: packed Bayer 4 通道(R/Gr/Gb/B, 每 2x2 单元无损重排为 1 个
  4ch 位置, 分辨率减半, SID 同款吃法) + 第 5 通道增益元数据
- 输出: 全分辨率 sRGB(bilinear 2x 上采样, 避免反卷积棋盘伪影)
- 规模: 3 级编码器 + 跳连, 0.47M 参数(SID 原版 ~8M 的 6%)
- 损失: L1 + 0.1x 梯度损失(抑 L1 过糊)

### 3.3 两个关键技巧(实测有效)

1. **曝光增益压缩(SID 技巧)**: 输入 in = clip(raw x g, 0, 1),
   g = gain_ref/exposure。所有曝光的输入亮度归一到同一尺度, 网络
   唯一要处理的变量是噪声大小。坑: gain_max 必须 >= gain_ref/最低
   曝光, 否则最暗档被截断变暗, 引入"曝光歧义"(实测色度恢复明显
   变差: 1/100 照度下 PSNR 差 3.4 dB, 修正后追平)。
2. **增益元数据条件化(ISO-aware)**: 第 5 输入通道是归一化增益
   (真实相机有 ISO/曝光时间元数据)。网络据此调降噪强度 —— 同样
   亮度的输入, 高增益多滤, 低增益少滤。

### 3.4 生成式扩展: 条件 Rectified Flow(flow_model.py)

在回归 U-Net 之外增加一条生成式路线 —— 扩散/流模型同源, 都学一个
把噪声分布搬运到数据分布的速度场; 本仓库实现 **Rectified Flow**
(流匹配, SD3/Flux 的训练范式): 直线路径 x_t=(1-t)x0+t·eps,
MSE 回归速度场 v=eps-x0, Euler ODE 1~8 步采样 —— 少步采样是 CPU
可 demo 的唯一形态(DDPM 随机采样要几十~上千步, 训练也是数小时起)。

- 模型 FlowUNet 0.48M: 输入 = x_t(3ch) + t 常数图(1ch) + 条件
  (packed 5ch 双线性上采样到全分辨率), 全分辨率无上采样头
- 训练与回归 U-Net 完全同源(同数据管线/同曝光域/同评估口径),
  唯一变量是"确定性回归 vs 生成式采样", 保证对比公平
- 面试叙事: "扩散和流是同一速度场的两种采样形式, 我选流的少步
  ODE 形态因为延迟可控"

## 4. 踩坑记录(都是 ML 工程的真实教训)

1. **单场景训练 = 背答案**: 最初用单一场景的 24 个翻转变体训练,
   val_l1=0.0058 非常好看, 但 held-out 场景上色度推断崩溃(输出
   彩虹色块) —— 验证集与训练集同场景, 指标是假象。修正为在线随机
   场景后 val_l1 升到 0.07(真实难度), 泛化正常。
   教训: **训练/验证/测试的场景隔离是 ML 评估的基本纪律**。
2. **增益截断的曝光歧义**: 见上文技巧 1。
3. **公平对比**: 传统路径必须给全套装备(LSC 白场标定开启)。
   首版对比忘了开 LSC, 传统路径白白吃暗角/色偏的亏, 那不是公平
   比较(修正后传统 PSNR +8.6 dB)。
4. **基线噪声口径不一致(重要修正)**: 最早版本里传统基线的 RAW 用
   弱噪声(sigma_read=0.8)生成, 而模型输入用强噪声(3.0)——同一个
   "相机"在两条路径上用了两种噪声, 得出了"传统在 1/50 领先"的
   错误交叉点结论。统一口径后传统基线全线大幅回落(1/50: 23.10→
   16.31 dB), 交叉点消失。教训: **对比实验里所有路径必须同一起源
   的同一帧输入, 生成输入的代码要共享而不是各写一份**。

## 5. 结果(held-out 场景, 训练从未见过的布局配色)

### 5.1 传统 vs 端到端(统一强噪声口径, SID 域)

| 曝光 | 照度 | 传统 ISP(数字增益放大) | U-Net 端到端 | 差值 |
|------|------|------------------------|--------------|------|
| 0.02 | 1/50 | 16.31 dB | 20.97 dB | +4.65 dB |
| 0.01 | 1/100 | 12.10 dB | 20.42 dB | +8.32 dB |
| 0.0075 | 1/133 | 10.98 dB | 20.47 dB | **+9.48 dB** |

(6000 iter / 0.47M 参数 / ISO 条件化模型; 数字可由
`python ml/eval_demo.py` 复现)

SID 噪声域(sigma_read=3DN + shot 0.08)下端到端全面反超, 且照度越暗
优势越大 —— 传统链"分模块处理"在信息被噪声淹没后不可逆损失(先
降噪会糊掉真细节, 后拉伸会放大噪声 xN), 端到端把去噪/去马赛克/
色彩恢复联合优化。这正是 SID 论文的核心叙事在本 demo 的复现。

注: 若把噪声降到温和域(sigma_read=0.8), 传统基线在 1/50 照度内
仍能领先 —— 传统先验在"它被标定的域"里依然强大, 这就是"结论要
限定域"的含义。

### 5.2 回归 vs 生成式(同一任务同一口径, eval_flow.py)

| 方法 | PSNR | 锐度/GT | 单帧延迟(CPU) |
|------|------|---------|----------------|
| 传统 ISP(增益放大) | 16.31 | 22.9(噪声抬高频) | 0.60 s |
| 回归 U-Net | **20.97** | 0.59(过糊) | **0.05 s** |
| Flow 1 步 ODE | 17.23 | 2.75 | 0.16 s |
| Flow 2 步 ODE | 18.26 | 1.23 | 0.31 s |
| Flow 4 步 ODE | 18.39 | **0.99(贴 GT)** | 0.57 s |
| Flow 8 步 ODE | 18.51 | 0.87 | 1.07 s |

(1/133 照度点为 18.12/18.20, 规律一致; 可由 `python ml/eval_flow.py`
复现)

**回归 vs 生成的取舍正是本文的"实际应用"结论**:
- 回归模型输出条件均值: PSNR 最高但过糊(锐度只有 GT 的 0.6),
  这是 L1/MSE 回归的数学性质, 不是训练问题;
- 生成式模型采样后验样本: 锐度贴 GT(4 步即 0.99), 但 PSNR 低
  ~2.5 dB 且带采样色斑, 延迟随步数线性增长;
- 延迟对比推翻一个直觉: 流模型 4 步(0.57s)与传统 12 级 numpy
  pipeline(0.60s)同量级 —— 生成式方法进不了的是 preview 链路
  (要 30fps), 拍摄瞬间的单帧增强完全可行;
- 落地形态: preview 用回归模型, 成片用少步生成式精修 —— 两级
  架构对应真实产品"预览/拍照"双链路。

定性(见 output/flow_compare_expXXX.png, 左起 GT/传统/U-Net/Flow):
传统被色噪淹没; U-Net 干净但边缘发糊; Flow 纹理锐利、残余采样
色斑 —— 与上表指标一一对应。

## 6. 复现

```bash
python ml/train.py --iters 6000       # 回归 U-Net, CPU ~13min
python ml/train_flow.py --iters 5000  # 条件 Rectified Flow, CPU ~17min
python ml/train_reflow.py             # reflow 蒸馏(8 步 -> 1 步), ~5min
python ml/eval_demo.py                # 传统 vs U-Net(held-out 三档曝光)
python ml/eval_flow.py                # 传统/U-Net/Flow/蒸馏 四方对比
python ml/run_ml_camera.py            # 预览/拍照双链路 demo
python run_real_raw.py                # (对照)传统 RAW 文件直通路径
```

## 7. 剩余优化空间(按优先级)

(2026-09-16 更新: 原三项 P0 已完成 —— AE 修复见 optimization_report.md,
LPIPS 已接入 eval_flow, reflow 蒸馏已实现 1 步 0.16s)

1. **P0 多轮 reflow + 扩缓存**: 一轮蒸馏 1 步 +0.3~0.4 dB, 多轮可
   继续逼近 8 步教师;
2. **P0 生成式色斑**: LPIPS 显示采样色斑是 Flow 最大短板, 损失加
   色度项或提升容量;
3. **P1 噪声模型真实化**: 加入行噪声/DSNU/热像素, 让网络见过真实
   噪声结构 —— 这是迁移到真机的前置条件。
4. **P1 混合方案**: 传统 pipeline 主体 + ML 替换 BNR+Demosaic 段,
   保留可解释性与 3A 控制; preview/成片双链路已 demo(run_ml_camera)。
5. **P2 元数据扩展**: 条件通道目前只有增益, 可扩展色温/光圈/焦距;
   生成式还可加文本/风格条件(真实产品已有个性的"胶片感"生成)。
6. **P2 量化部署**: 0.5M 参数 INT8 后 <0.5MB; preview 0.055s 单帧
   需量化+batch 上 30fps(面试可讲量化部署)。

## 8. 面试要点速查

- 为什么端到端能"看到黑暗": 网络直接在 RAW 域(黑电平校正后)工作,
  没有中间量化和 gamma 变换的信息损失, 去噪/去马赛克/色调映射联合
  优化 —— 本质是"用数据先验替代人工先验"。
- 训练数据怎么来: 真机拍短曝-长曝对(SID); 没有真机时用仿真器合成
  (本仓库), 但要主动讲清 sim-to-real 差距(噪声模型/动态范围)。
- ISO 条件化: 增益作元数据输入, 降噪强度自适应 —— 对应真实产品里
  的 ISO-aware denoising。
- 扩散 vs 流(必考新热点): 两者同源 —— 都学噪声到数据的速度场;
  DDPM 是随机采样(慢), 流匹配是确定性 ODE(可 1~8 步), SD3/Flux
  已转向流匹配。产品里生成式的位置: 不在 preview(30fps 硬约束),
  在成片单帧增强/风格化, 我实测 4 步 ODE 延迟与传统 pipeline 同量级。
- 回归 vs 生成: 回归=条件均值(PSNR 高, 过糊), 生成=后验采样
  (锐度贴 GT, PSNR 低 ~2.5 dB + 采样色斑); 选型看链路: preview
  选回归, 成片精修选生成, 这就是"预览/拍照"双链路。
- 评估纪律: 训练/验证/测试场景隔离; 传统基线要给全套标定装备;
  **所有路径的输入必须同一帧同一噪声口径**(本仓库踩过: 基线噪声
  不一致导致假的"交叉点"结论); 报告"在什么噪声/照度域"的结论。
- 产品落地: 端到端是研究叙事, 落地是"传统 3A/标定 + ML 降噪/
  插值"的混合架构, 因为 3A 要可解释可回退。
